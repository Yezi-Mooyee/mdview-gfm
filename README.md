A featherweight Markdown viewer built on **GitHub's own renderer** — a native window for reading, plus a small CLI that converts Markdown to HTML.

## Why it exists

Every other "GitHub-style" Markdown viewer out there (MarkText, Obsidian, Typora, browser extensions…) actually renders with markdown-it, marked or goldmark, and only copies the *look*. This one uses [github/cmark-gfm](https://github.com/github/cmark-gfm) — the parser that *defines* the GFM specification — with GitHub's official [github-markdown-css](https://github.com/sindresorhus/github-markdown-css). Tables, task lists, footnotes, strikethrough, autolinks and raw HTML behave exactly as they do on GitHub, because it is the same parser and the same stylesheet.

## Highlights

- **Genuinely tiny.** A few dozen KB of Python source, two runtime dependencies, no build step, no framework. The app itself is called `mdview`; the repository is `mdview-gfm` so it is easier to find.
- **Smooth in daily use.** Scrolling long documents, switching files, changing themes and zooming are all instant — verified on a low-power, HiDPI tablet-class machine. Only the window appearing takes a moment; see [Startup time](#startup-time).
- **Green software.** No installer, no registry writes, no `PATH` surgery. Drop the folder anywhere and run it; delete the folder and it is gone. See [Where your data lives](#where-your-data-lives).
- **HiDPI done properly.** Crisp text at 200% scaling instead of a bitmap-stretched blur.
- **Link preview on hover.** Hovering a link shows its target in a status bar at the bottom, and local files are shown as Windows paths rather than `file://` URLs.
- **Drag & drop.** Drop a `.md` file onto the window to open it.

## Quick start

### 1. Requirements

| Requirement | Version |
|:------------|:--------|
| OS | Windows 10 / 11 — the GUI renders through Edge WebView2 |
| Python | 3.8 or newer |

### 2. Install the dependencies

```powershell
python -m pip install pycmarkgfm pywebview
```

`pycmarkgfm` (a 142 KB wheel) is used by both the GUI and the CLI. `pywebview` is only needed by the GUI — for the CLI alone, `pip install pycmarkgfm` is enough.

There is nothing to build: keep the scripts and the three `github-markdown-*.css` files together and you are done.

### 3. Start the GUI

Double-click **`mdview-gui.pyw`**. The `.pyw` extension makes Windows run it with `pythonw`, so no console window flashes.

From a terminal:

```powershell
.\mdview-gui.cmd                  # empty window, pick a file from the toolbar
.\mdview-gui.cmd README.md        # open a file directly
```

You can also drag a `.md` file onto `mdview-gui.pyw`, or onto the window once it is open.

### 4. Use the CLI

The CLI is simply a Markdown-to-HTML converter: it writes a standalone HTML file to a fixed path under `%TEMP%\mdview\` and opens it in your browser.

```powershell
.\mdview.cmd README.md                 # render and open in your default browser
python mdview.py README.md --no-open   # just print the generated file's path
type notes.md | python mdview.py -     # read from stdin
```

| Option | Effect |
|:-------|:-------|
| `--out PATH` | Write the HTML somewhere else |
| `--no-open` | Generate only, don't open a browser |
| `--safe` | Fall back to cmark-gfm's strict filtering (raw HTML escaped) |
| `--css PATH` | Use a different stylesheet |
| `--title TEXT` | Set the page title |

## Where your data lives

Nothing is installed and nothing is hidden inside the project folder. Everything written goes to three places outside it:

| Path | What |
|:-----|:-----|
| `%APPDATA%\mdview\config.json` | Theme, zoom level, recent files |
| `%APPDATA%\mdview\webview\` | Edge WebView2 profile cache (GUI only) |
| `%TEMP%\mdview\` | HTML generated by the CLI and the "open in browser" button |

Delete those three and you are back to a pristine state; delete the project folder and the program is uninstalled.

## Interface

| Control | What it does | Shortcut |
|:--------|:-------------|:---------|
| ← / → | Back / forward through visited documents | `Alt+←` / `Alt+→` |
| Home | Return to the welcome page; it counts as a new step, so Back still returns to the document you were reading | `Alt+Home` |
| Open… | File picker | `Ctrl+O` |
| Reload | Re-read the current file from disk, keeping your scroll position | `F5` |
| Browser | Open the same rendered result in your default browser | `Ctrl+B` |
| − / + | Zoom 70%–200% | `Ctrl+-` / `Ctrl+=` |
| Auto / Light / Dark | Theme; Auto follows the system | — |

Behaviour worth knowing:

- Only the **left mouse button** triggers links. Middle and right click open nothing (right click still shows the context menu).
- Links never open inside the window — local Markdown switches the document, web links go to your browser, other files go to their default program.
- **Recent files** refresh every time you visit the home page. Entries whose file has gone are kept and marked as missing, so a file you moved is still findable. Two instances running side by side see each other's files.
- If a file cannot be read — deleted, renamed, or a folder — the name in the toolbar says why, with a countdown and a close button beside it. Hovering the message pauses the countdown, outlines it, and shows the full path in a tooltip. Your document stays on screen; only the page you reached by Back/Forward is replaced by an explanation, since those re-read the file from disk.
- Your theme, zoom level and recent files are remembered between runs.

## Startup time

The window appears, then the content follows a moment later — that gap is the Edge WebView2 runtime initialising, and it is unrelated to document size. On the test machine it ranged from about 6 to 20 seconds depending on system load; the app's own code accounts for roughly 1.3 s of it. Once the window is up, everything is instant.

## About Edge WebView2

The GUI renders through the **Microsoft Edge WebView2 Runtime**. It is a system component rather than a browser you have to use:

- It ships with Windows 11 and is present on essentially every up-to-date Windows 10 machine.
- You do **not** have to use the Edge browser, or keep it installed. What matters is the WebView2 *Runtime*.
- If it happens to be missing, install the Evergreen Runtime from Microsoft: <https://developer.microsoft.com/microsoft-edge/webview2/>

The CLI does not need WebView2 at all.

## How it differs from github.com

The renderer is identical, but GitHub applies some post-processing that this does not:

- **Syntax highlighting** — GitHub colours code server-side; here you get the `<pre lang="...">` structure without colours.
- **Emoji shortcodes** — GitHub turns `:smile:` into 😄; here it stays as written.
- **Heading anchors** — GitHub gives every heading an `id` for anchor links; here there are none.
